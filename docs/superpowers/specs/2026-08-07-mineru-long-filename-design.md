# MinerU 超长文件名处理设计

## 背景

MinerU 解析链路当前直接从原始文件名生成临时 PDF 名称、API multipart 上传名称、临时输出目录、ZIP 文件名以及结果 JSON 候选名称。Linux 文件系统通常限制单个路径组件不超过 255 字节。一个能够作为原始 PDF 文件名存在的名称，在追加 `_auto_<random>`、`.zip` 或 `_content_list.json` 后仍可能超过限制。

已有的输出目录兼容逻辑可以处理 MinerU 版本间的目录层级差异，但不会限制任何名称的 UTF-8 字节长度。因此，超长名称可能在调用 MinerU API 之前、保存 ZIP 时或读取结果时失败。

## 目标

1. 保留数据库、任务记录和界面中的原始文件名。
2. 为 MinerU 内部临时文件、上传名称和输出文件生成稳定、可读且有界的工作名称。
3. 避免截断导致的同名前缀碰撞。
4. 不破坏现有短文件名及 MinerU 输出目录兼容逻辑。
5. 不重命名调用方提供的本地源文件。

## 非目标

- 修改数据库、MinIO 对象名或前端展示名称。
- 修改 MinerU API 协议或服务端命名规则。
- 解决整个路径超过文件系统 `PATH_MAX` 的问题。
- 重构 MinerU 的模型配置、网络请求或内容转换逻辑。

## 方案比较

### 方案 A：可读前缀加稳定哈希

仅当规范化后的文件 stem 超过字节预算时，在完整 UTF-8 字符边界处截断，并追加下划线和原 stem 的 12 位 SHA-256 摘要。

优点：日志仍可辨认，名称稳定，不同长名称的碰撞概率极低。缺点：需要一段独立的 UTF-8 安全截断逻辑。

### 方案 B：始终使用完整哈希

所有 MinerU 工作名称都使用原 stem 的 SHA-256。

优点：实现和长度推导最简单。缺点：短文件名也失去可读性，排障日志难以关联文档。

### 方案 C：只截断

直接按字节预算截断原 stem。

优点：实现最少。缺点：共享长前缀的文件会生成相同工作名称，无法满足防碰撞要求。

采用方案 A。

## 命名规则

- MinerU 工作 stem 的最大长度为 180 个 UTF-8 字节。
- 180 字节预算为常见的 255 字节单组件限制预留至少 75 字节，供 `_content_list_v2.json`、`_<method>_<random>`、`.zip` 等派生后缀使用。
- 继续移除 ASCII 空格，以保留当前 MinerU 兼容行为。
- 空 stem 使用 `document`。
- 不超过预算的 stem 保持不变。
- 超过预算时，结果格式为 `<完整字符前缀>_<12位SHA-256>`。
- 摘要基于移除空格后的完整 stem 计算，同一输入始终得到同一工作名称。
- UTF-8 截断不得产生半个多字节字符。

## 数据流

`parse_pdf` 在接触文件系统前生成一次工作 stem，后续链路全部复用它：

1. 对二进制输入，在固定前缀的临时目录中写入 `<working_stem>.pdf`。
2. 对本地文件输入，如果原名称已等于工作名称，直接读取原文件。
3. 对本地文件输入，如果需要移除空格或缩短名称，将原文件复制到固定前缀的临时目录，不移动或重命名原文件。
4. `_run_mineru_api` 从短临时 PDF 获取 stem，用于 multipart 上传名称、输出目录前缀和 ZIP 名称。
5. `_read_output` 使用相同的短 stem 查找 MinerU 结果；现有显式目录候选和递归兜底保持不变。
6. 解析完成后清理输入临时目录；外部 `output_dir` 和 `delete_output` 语义不变。

## 日志和错误处理

- 只有名称发生变化时才记录原始 stem 到工作 stem 的映射。
- 日志映射用于排障，不修改任务展示名称。
- 本地源文件不存在时，在创建临时副本前沿用现有 `FileNotFoundError` 行为。
- 复制、写入或清理异常沿用当前解析异常传播与最佳努力清理策略。

## 测试

在 `test/unit_test/deepdoc/test_mineru_parser.py` 中覆盖：

1. 短 ASCII/中文名称保持不变。
2. 超长中文名称生成不超过 180 UTF-8 字节的工作 stem，且没有损坏字符。
3. 同前缀不同尾部的长名称生成不同哈希后缀。
4. 二进制 PDF 解析使用短临时名称，并将同一 stem 传给结果读取。
5. 本地文件需要改名时使用临时副本，原文件名称和内容保持不变。
6. 现有 MinerU 嵌套 `auto` 目录和递归查找测试继续通过。

## 验收标准

- 任意原始 stem 都不会让 MinerU 工作 stem 超过 180 个 UTF-8 字节。
- 已知最长派生文件名保持低于 255 个 UTF-8 字节。
- 长中文文件名可以完成临时写入、API 命名和结果查找的数据流。
- 原始文件名和本地源文件不被修改。
- MinerU 定向单元测试、Python 编译检查和相关 Ruff 检查通过。
